# 翻斗星谱开发路线图

本文保留分阶段设计依据。当前版本已完成公开浏览、D1、Bearer 登录与权限、本人编辑、附件/事迹和管理端基础功能；未完成项继续作为后续增强。星空主题与树谱浏览体验保持不变。

## 近期交付顺序

### 1. 稳定公开浏览（已交付）

目标：接口异常、空数据和未知人物都不会让用户卡在页面中。

- 树谱加载失败时保留演示回退，同时显示“重新连接”操作和当前资料来源。
- 空树谱与请求失败分开处理；空树谱不自动伪装成演示数据。
- 人物详情 404 显示明确的“档案不存在”，并提供返回星谱入口；其他错误可重试。
- 从星谱进入详情时记录人物 ID；返回后恢复该节点的简介窗口和焦点位置。
- 在师傅、学生之间跳转后，仍可一键定位到当前人物在星谱中的节点。
- 搜索覆盖姓名、昵称、届次、去向分类和去向名称；未知去向不参与视觉推断。

验收：断开 API、返回空数组、访问不存在的人物 ID、连续浏览三层师徒关系时，页面均有可操作的下一步。

### 2. D1 数据贯通（已交付）

目标：用 D1 取代 `apps/api/src/data.ts` 中的演示数组，保持现有响应契约。

- 增加本地和远程 D1 的独立配置，迁移命令明确指定环境。
- 建立 repository 层，集中处理人物、届次、师徒边和详情查询。
- `/api/tree` 在一次请求中返回节点与有效边；孤立人物仍可见，无效 mentor 引用不生成边。
- `/api/people/search` 使用参数化查询，统一限制返回数量并覆盖去向字段。
- 增加最小种子数据脚本，仅用于本地开发，不包含真实成员资料。

验收：相同契约测试可分别运行在演示 repository 和本地 D1 repository 上；树谱、搜索和详情的 ID 保持一致。

### 3. 登录与权限（已交付 Bearer 版本）

目标：公开浏览和档案编辑形成清晰的权限边界。

- 当前使用邮箱密码映射到 `users`，人物与账号保持分离；外部身份提供方仍是后续选项。
- 当前会话使用 8 小时 Bearer token，数据库只存 token hash；生产通过 HTTPS 与精确 CORS 来源保护传输。
- `member` 只能修改绑定人物允许自助维护的字段；`admin` 才能修改师徒关系、届次、状态和去向分类。
- 所有写接口默认拒绝未登录用户，读接口维持当前公开范围。
- 日志记录操作者、目标资源、请求 ID 和结果，避免记录令牌或私密附件 URL。

验收：未登录、普通成员、管理员三类会话均有接口级权限测试；前端隐藏操作入口不能替代服务端鉴权。

### 4. 本人资料编辑（已交付）

目标：成员可以安全地完善自己的昵称、简介、头像和去向。

- 新增 `GET /api/me/profile` 与 `PATCH /api/me/profile`，输入使用共享 Zod schema。
- 每次修改必须提交 `version`；版本冲突返回 409，并让用户选择重新加载后再编辑。
- 去向使用稳定枚举与自由文本名称组合，例如 `company` + 公司名、`postgraduate_985` + 学校名；显示标签与业务值分离。
- 关系、届次、在读/毕业状态不纳入普通成员自助编辑范围。
- 编辑页保留未提交状态、离开提醒、提交中禁用和失败重试。

验收：两个会话同时编辑同一人物时，后提交者收到冲突提示；刷新后可继续编辑，数据不会静默覆盖。

### 5. 头像与附件（基础流程已交付）

目标：文件上传失败不会留下可见的残缺档案或无法追踪的对象。

- API 先在 D1 创建 `pending` 附件，再签发短时 R2 上传地址。
- 上传完成后由确认接口校验对象存在、大小和 MIME 类型，再切换为 `ready`。
- 页面只展示 `ready` 附件；定时清理超时 `pending` 记录和孤立 R2 对象。
- 私密附件通过鉴权下载接口或短时签名 URL 访问，不暴露永久公开地址。
- 限制头像类型、像素、体积，并在服务端重新编码或进行内容检查。

验收：上传中断、确认失败、重复确认、删除附件和越权下载均有测试；失败对象可被清理任务回收。

### 6. 管理端与关系维护（基础流程已交付）

目标：管理员能维护成员和师徒关系，同时保护树谱结构。

- 人物、届次、状态、去向和师徒关系使用独立表单，减少一次修改的影响范围。
- 修改 mentor 前检查自指、祖先环和不存在的 ID；冲突时返回可读错误。
- 删除人物默认改为停用或软删除；涉及关系重排时要求明确选择后继处理方式。
- 每次管理操作写入审计记录，并支持查看变更前后值。

验收：构造自指和多层环均会被 API 拒绝；合法跨届关系仍能生成长连接线。

## 契约与状态约定

- API 成功统一为 `{ data, meta? }`，失败统一为 `{ error: { code, message, fieldErrors? }, requestId? }`。
- 人物状态的业务文案固定为“在读”和“毕业”；数据库值与中文显示文案分离。
- 去向类型使用稳定业务值，前端样式只依据已知类型映射；未知类型显示普通标签，不能导致页面报错。
- `404` 表示资源不存在，`409` 表示版本或关系冲突，`422` 表示字段校验失败，`500` 不向客户端泄露内部细节。
- 数据库迁移只前进，不修改已经发布的迁移文件；字段替换采用新增、回填、切换、清理四步。

## 持续验证

每个切片至少运行以下检查：

- 共享 schema 和 API 契约测试。
- Web 与 Worker 生产构建。
- 树谱首页、人物简介、详情直达、关系跳转和返回定位的浏览器冒烟测试。
- D1 迁移在空数据库与上一版本数据库各执行一次。
- 写功能上线前补充权限、并发冲突和文件上传失败路径测试。
